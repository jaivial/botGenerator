# BotGenerator Evolution Staging

Isolated staging-only Evolution API stack. Evolution API `2.4.0-rc2` is a release candidate for validation only. Do not use a production WhatsApp number in this stack.

## Scope

- Official Evolution API image is pinned to `evoapicloud/evolution-api:2.4.0-rc2` and OCI index digest `sha256:b4a18ed5213d34a0845f841ba9afae1b67940457d021b42af863eae67dc2cfbd`.
- Project name, container names, bridge network, and volumes use the `botgenerator-evolution-staging` prefix.
- PostgreSQL, Redis, and instance data persist in dedicated named volumes.
- Only Evolution API binds a host port: `127.0.0.1:8108`. PostgreSQL and Redis have no host ports.
- Built-in manager is disabled and no manager/frontend container exists. Evolution API remains local-only.
- Webhooks are disabled. No WhatsApp instance is created, linked, or QR-generated by deployment.
- Telemetry and unused integrations are disabled. Service restart policy, health checks, resource limits, and local log rotation are configured.

## Install Or Update

Run from repository checkout. Installer copies tracked Compose/scripts into `/opt/botgenerator-evolution-staging`; it never reads or changes `/opt/newvillacarmen-evolution`.

```bash
sudo ./deploy/evolution-staging/install.sh
```

First install creates `/opt/botgenerator-evolution-staging/.env` with unique 256-bit PostgreSQL and API credentials. It is `root:root`, mode `0600`, and is never printed. Later installs preserve existing credentials and refresh only tracked Compose/scripts.

Installer pulls images, starts stack, waits for Docker health checks, and runs connection health, including authenticated `GET /instance/fetchInstances`. It does not create an Evolution instance, request a QR code, or configure any webhook.

## License Activation

Evolution API `2.4.0-rc2` requires free community activation before business endpoints serve traffic. Existing `AUTHENTICATION_API_KEY` is presented only inside the API container and is never printed or placed on a host process command line. If Evolution does not accept it as a licensing key, public `GET /` and `GET /license/status` remain available but business endpoints return `HTTP 503 LICENSE_REQUIRED`.

First-time activation requires the official browser flow initiated by `GET /license/register`; do not invent or commit licensing credentials. Headless activation with `EVOLUTION_OPERATOR_EMAIL` is allowed only for an operator email previously registered with Evolution Foundation. Keep any operator email in root-owned `/opt/botgenerator-evolution-staging/.env`, never in tracked files or command output. After activation, rerun the installer or health script.

Validation on 2026-07-31 confirmed the rc2 container is healthy, `GET /` returns `200`, and `GET /license/status` returns `200` with status `inactive`. Authenticated `GET /instance/fetchInstances` returns `503`; activation therefore requires the manual flow or a previously registered operator email. Existing staging database, Redis, instance volume, and instance record remain present. No QR or re-pair was attempted while the activation gate prevents session validation.

## Verify

Commands below do not print credentials:

```bash
sudo /opt/botgenerator-evolution-staging/scripts/health.sh
sudo docker compose --project-name botgenerator-evolution-staging --env-file /opt/botgenerator-evolution-staging/.env --file /opt/botgenerator-evolution-staging/compose.yaml ps
sudo ss -ltn '( sport = :8108 )'
```

Expected listener is `127.0.0.1:8108`; no listener is expected for staging PostgreSQL or Redis. The health script verifies all container health checks, PostgreSQL connection readiness, Redis response, public `GET /`, and authenticated business `GET /instance/fetchInstances` without displaying response content or credentials. Both API requests include the allowed local `Origin` required by this restricted CORS configuration.

## Live Contract Test

`scripts/contract-test.sh` is opt-in and local-staging-only. It requires both instance and recipient arguments, never prints API keys, does not test calls, and does not change provider or Evolution configuration. No message is sent when `--recipient` is omitted. Supply approved staging recipient `34692747052` explicitly:

```bash
sudo /opt/botgenerator-evolution-staging/scripts/contract-test.sh \
  --instance YOUR_STAGING_INSTANCE \
  --recipient 34692747052
```

Script checks WhatsApp number existence before sending text, reply-only buttons, URL-only buttons, list, and contact payloads. It records accepted message IDs and queries their statuses from isolated Evolution PostgreSQL. Run optional inbound phase only with real inbound message ID belonging to supplied recipient:

```bash
sudo /opt/botgenerator-evolution-staging/scripts/contract-test.sh \
  --instance YOUR_STAGING_INSTANCE \
  --recipient 34692747052 \
  --inbound-message-id REAL_INBOUND_MESSAGE_ID
```

Optional phase adds and removes reaction, then marks inbound message read. It never initiates or rejects calls.

## Backups

Run a backup manually:

```bash
sudo /opt/botgenerator-evolution-staging/scripts/backup.sh
```

Default output is `/var/backups/botgenerator-evolution-staging/<UTC timestamp>/`, root-owned mode `0700`. Each backup contains a PostgreSQL custom dump, compressed Evolution instance data, and SHA-256 checksums. Files are mode `0600`. Script does not source, print, or place runtime credentials on command lines.

Recommended cron policy, not installed by this repository:

```cron
17 2 * * * root /opt/botgenerator-evolution-staging/scripts/backup.sh >/var/log/botgenerator-evolution-staging-backup.log 2>&1
43 2 * * * root /opt/botgenerator-evolution-staging/scripts/health.sh >/var/log/botgenerator-evolution-staging-health.log 2>&1
```

Send backup output to off-host encrypted storage and define retention externally before relying on recovery.

## Webhook Decision

Existing Nginx forwarding for `/api/bot/` remains unchanged. BotGenerator now has authenticated Evolution webhook endpoint and durable deduplication, but staging deployment does not configure or expose it automatically. Do not expose Evolution dashboard/API through Nginx.
